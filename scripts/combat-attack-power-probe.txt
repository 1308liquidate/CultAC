Combat reach attack-power probe

The expanded smoketest is in ../CultAC-old/mcp-client-smoketest. The patch beside
this file reproduces those harness changes in another checkout of that harness.
Apply it from the harness root with git apply /path/to/combat-attack-power-smoketest.patch.

Run from the anticheat checkout:
  scripts/run-local-combat-attack-power-probe.sh

Use SMOKETEST_REPO, SMOKETEST_WORKSPACE_MANIFEST, SMOKETEST_PLUGIN_JAR,
SMOKETEST_ARTIFACT_ROOT and SMOKETEST_BASE_PORT to select prepared binaries and
artifact locations. The wrapper pins an existing anticheat jar and does not
rebuild or modify anticheat sources. Gradle arguments can follow the command.
The verified local workspace uses the vanilla Minecraft 26.2 client and Paper
26.2 build 111; use a compatible prepared manifest when targeting another version.

For latency coverage, add:
  -Psmoketest.inboundLatencyMillis=100 -Psmoketest.outboundLatencyMillis=100
  -Psmoketest.inboundJitterMillis=20 -Psmoketest.outboundJitterMillis=20

Both bundled and unbundled entity tracking modes run 8 bots for 1,000 ticks.
Each bot rotates swords, axe, trident, pickaxe, a second sword of the same type,
a single honey bottle, golden apples, bow, and an empty hand with an offhand
shield. Cadences include weak, charged, and near-threshold attacks, rapid slot
changes and attacks in the tick of a slot change. Movement and item use come
from vanilla mouse/key inputs. Fixture health and floor size keep the clients
alive and in the arena long enough to complete the sequence.
The cycle also aborts food use before later completing consumption, releases
use input between phases, alternates attackers and shield users, and finishes
with fast swaps between different weapon classes. Active used item/hand and
vanilla use starts/stops are observed directly. The support plugin records
successful shield blocks, completed consumption, bow shots and early releases.
At teardown, already queued outbound packets finish at their scheduled latency
before the clients disconnect; no extra client ticks or attacks are generated.

The harness reads Player#getAttackStrengthScale(0.5F) and its delay immediately
after MultiPlayerGameMode#ensureHasSentCarriedItem and before its attack packet
and local cooldown reset. It sends an observation-only custom payload before
that vanilla attack, preserving the outbound latency queue's packet order.
The Paper support plugin reads ClientAttackStrength and ClientCombatAttributes
on the packet owner before the attack reaches the anticheat, including attacks
that the anticheat subsequently cancels. It never writes to that model.

The interval uses the model's min/max ticker and bundle-proven attack-speed delay,
including PacketPlayerAttack's claimed-main-hand minimum reset. It reports exact
matches, contained uncertainty, and mismatches with the client value and bounds.
Missing/unpaired reports, insufficient observed scenarios, and disjoint power
bounds fail validation. Actual START_SPRINTING and STOP_SPRINTING packets and
local item-use/slot state are recorded separately. A fully charged classification
is the vanilla strict > 0.9F condition, distinct from reaching power 1.0F.

Reach geometry is captured at the same attack boundary. Minecraft#handleKeybinds
attacks before the local player/entity tick, and mouse rotation is applied after
ticks; post-tick geometry therefore cannot measure that attack faithfully. The
existing reach thresholds remain in place. Tests verify the timing correction
and that excessive reach still fails.

Vanilla sources read in the prepared MCP-Reborn tree:
  client/Minecraft.java: startAttack, handleKeybinds, tick
  client/multiplayer/MultiPlayerGameMode.java: attack
  client/player/LocalPlayer.java: aiStep, sendPosition
  world/entity/player/Player.java: tick, attack, getAttackStrengthScale
  world/entity/LivingEntity.java: tick, detectEquipmentUpdates
  world/item/component/Consumables.java: honey consumes for 2 seconds (40 ticks)
  network/protocol/game/ServerboundPlayerCommandPacket.java: sprint commands

Outputs per mode:
  combat-attack-power-metrics.txt
  combat-attack-power-observations.txt
  combat-use-metrics.txt (client use episodes and actual server outcomes)
  combat-reach-validation-summary.txt (aggregate)
The command exits nonzero when it finds a discrepancy. Retain that failure when
using the probe to investigate the unchanged anticheat; do not widen the bounds.

Recheck a captured raw server log with the compiled analyzer:
  java -cp /path/to/harness/build/classes/java/main \
    ac.grim.movementvalidation.AttackPowerMetrics /path/to/latest.log
This also validates the strict > 0.9F decision independently of numeric tolerance.
The original local evidence is in validation/combat-attack-power/REPORT.txt.
The packet-authoritative fix and its reruns are recorded under fix/.
Requested use/block/cancel counts from the corrected runs are in USE-COUNTS.txt.
